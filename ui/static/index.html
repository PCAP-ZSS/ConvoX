What is being computed

A picture is a grid of pixels. To filter it, each new pixel is made from the pixels around it: take a small square of neighbours, multiply each by a weight, and add them up. The weights decide the effect (blur or edges). The square's side is the filter size.

The versions you are comparing

  • Serial: one CPU core does every pixel in turn. This is the reference answer.
  • OpenMP: the picture's rows are shared between CPU threads working at the same time.
  • CUDA naive: the GPU has one worker per pixel. All data comes from the GPU's main memory.
  • CUDA + constant memory: the filter weights are kept in a small memory made for values every worker reads.
  • CUDA + shared tiles: each group of workers first copies the piece of picture it needs into a very fast memory, then works from that.

How the results are checked

Every version's output is compared pixel by pixel with the serial output. A version passes only if no pixel differs by 0.0001 or more. Times are the median of the repeats, after one warm-up run that is thrown away.

Why the GPU's "whole job" time is longer

The picture has to be copied to the GPU and the result copied back. For a single image this copying often takes longer than the filter, so the GPU's advantage looks smaller when the whole job is counted. The charts show both.
